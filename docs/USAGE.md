# 使用手册

[← 返回首页](../README.md) · [English](../README.en.md)

将本机 Codex 的项目和聊天记录导入 DeepSeek Harness，默认复用仍存在的原项目工作目录，原目录不存在时回退到 **「Codex 导入」工作区**；通过 **「Codex 导入」面板** 仍可统一浏览全部导入记录。按照 Harness 官方的独立 bundle 机制安装，无需修改 Harness 源码。

支持 **DeepSeek Harness 0.2.2-rc.1**，包括当前桌面版；Node.js 需要 **24.9 或以上**。Harness 的 API 尚未稳定，本插件锁定此版本的会话服务，升级 Harness 后应重新验证兼容性。

## 界面导入向导

v0.13.0 提供以下界面流程；带 JSON 参数的兼容命令仍可使用。下载发布包，或从源码运行 `npm ci`、`npm pack` 构建安装包。

1. 点击导入目录或侧栏的 **「导入对话」**，或执行无参数 `/codex-import preview`。
2. 选择 **「本地 Codex」** 或 **「ChatGPT 导出包」**。Codex 显示当前 dsh 实例检测到的目录（包含配置目录、默认目录和可用的 Berth 目录）；ZIP 可拖入或点击 **「选择 ZIP 文件」**，显示文件名与大小。
3. 点击 **「开始预览」**。ZIP 会先传输到当前连接的 dsh 实例的临时缓存并检查格式；此时不创建导入会话或复制附件。
4. 检查新增/更新计划、附件缺失、分支和重合提示，点击 **「确认导入 N 条对话」**。也可点击 **「更换来源或文件」** 返回；旧确认编号会失效。

「高级选项」默认折叠，可设置附件开关、是否包含归档、重合检查、其他 Codex 目录、目标目录，以及缺少账户 ID 时使用的 ChatGPT 稳定来源标识。界面记住上次选择的来源，不会自动开始导入。

ZIP 使用文件流传输到宿主认证的插件接口，单个压缩包上限 1 GiB（解压限制仍见下文）。临时文件使用随机目录与按会话绑定的文件编号，存放在 `$DSH_HOME/cache/codex-import/uploads`。文件准备取消或失败时删除部分文件；导入结束后删除暂存副本；空闲暂存约 30 分钟后自动清理。重启后旧编号失效，超过一天的中断残留在下次上传时清理。用户原始 ZIP 不修改。浏览器连接远程 dsh 时，文件会传到该远程实例；Codex 来源同样属于该实例所在机器。

无参数 `preview` 只打开向导；`preview {}`、带筛选参数的 `preview`、`run` 和 `sync` 继续直接开始预览，并保留原有确认流程。

## ChatGPT 导出包导入

v0.13.2 修复富文本显示：ChatGPT 的 `<box>`、`<row>`、表单和引用标记会整理为普通段落、列表、表格和静态选项。新导入时保留原始节点、只转换展示正文；升级插件后，已导入的 ChatGPT 助手消息也会通过 Harness 原生显示组件整理，无需删除或重新导入，原始历史日志不改写。用户粘贴的代码、围栏代码和行内代码保持原样，原交互表单不会执行。引用仅在导出元数据能明确匹配 ID 和网址时恢复链接，否则注明需回原对话核对。

v0.13.2 修复了 0.13.1 在真实 Harness 中因原生插槽依赖缺失而回退原文的问题，并支持 `Cite refs={[...]}` 多引用及独立出现的文字样式、徽章、链接、图表和自动化建议。图表中的结构化数据转为表格；自动化建议仅展示历史文字。这里的兼容指阅读内容，ChatGPT 的交互组件、脚本和任务不会在 Harness 中重新执行；导出未保留的引用链接也无法完整还原。

v0.12.0 起支持 ZIP 和解压后的目录，使用相同的预览与确认流程：

下载 v0.13.2 发布包，或从源码运行 `npm ci`、`npm pack` 生成 `dsh-plugin-codex-import-0.13.2.tgz`，使用下方的第三方插件安装方式安装。

```text
/codex-import preview {"source":"chatgpt","archivePath":"/absolute/path/export.zip"}
```

也可指定 `archivePath` 为解压目录，使用 `threadIds` 筛选原对话 ID，或设置 `importAttachments:false`。默认放入 `$DSH_HOME/imports/chatgpt`，工作区名称「ChatGPT 导入」，不推断本地项目目录。Codex 的默认入口和原项目分组规则保持兼容。

- 优先读取 `export_manifest.json` 的对话分片清单，同时支持 `conversations.json` 和 `conversations-*.json`；逐片读取，不将整个 ZIP 解压到磁盘。
- 从 `current_node` 沿 `parent` 还原当前路径，保留消息顺序。其他分支节点保存在可忽略的原始事件中，不加入默认续聊上下文；暂不提供分支切换或每个分支单独导入。
- 文本、图文和音频转写转为原生消息；导出中已有的思考和摘要转为 reasoning。系统和工具历史作为普通历史记录展示，不执行。未知内容保留原始描述。
- 联合附件指针、文件名映射和文件库元数据匹配 ZIP 内文件。`.dat` 按文件头识别图片、WAV 和 PDF；可恢复图片写入原生图片存储，音频和其他文件保存为文件附件。暂不提供专用音频播放器或转写服务。
- 缺失、损坏或超限的附件保留占位与原因，不从远程下载。文件库中未关联到当前路径的文件不单独导入。Pages、Sites、群聊列为未处理内容，不转换为个人会话。
- ZIP 限制为 50,000 个文件、合计 4 GiB 解压内容；单个 JSON 文件最多 256 MiB，附件受 `maxAttachmentBytes`（默认 100 MiB）和 Harness 自身限制。拒绝路径穿越、符号链接、加密 ZIP、重复成员和 CRC 损坏。

**重复导入与重合处理：** 默认以 `user.json` 的账户 ID 摘要、原会话 ID 和目标目录识别来源；ZIP 改名、移动或重新导出不会改变同源身份。相同内容跳过，新增和修订追加到原副本，保留 dsh 续聊，源端减少的内容不从 dsh 删除。更换目标目录仍属于不同副本范围。缺少账户 ID 时必须显式提供稳定的 `sourceId`，同一账户后续保持一致；显式更换 `sourceId` 会创建独立来源。

ChatGPT 预览默认只读扫描 dsh 当前会话，提示相同文本序列和相同长消息（至少 80 字符）。内容相同不证明来源相同，跨来源不自动合并、覆盖或跳过；只有来源身份相同才走增量同步。`checkOverlap:false` 可关闭内容扫描。该扫描不作语义相似判断，不是完整的附件或分支等价证明。无法读取的会话会显示警告。

ChatGPT 确认计划同时锁定导出包内容摘要；预览后导出包发生变化，需要重新预览。此规则比 Codex 本地持续更新日志的确认规则更严格。

开发者可对导出包和本机 Codex / dsh 做独立的只读重合检查：

```sh
npm run audit:chatgpt -- /absolute/path/export.zip
```

默认检查 `CODEX_HOME`、`~/.codex` 和 `$DSH_HOME`（默认 `~/.dsh`）；可重复指定 `--codex-home /path`，并通过 `--dsh-home /path` 或 `--source-id stable-id` 覆盖。结果只输出统计、匹配 ID 和读取错误，不输出对话正文。读取本地 SQLite 消息，缺少正文时回退到已索引的 JSONL；dsh 每条会话只读取最新日志版本，避免将迁移备份重复计数。检查过程不修改会话，不执行导入。

## 安装到 Harness 桌面版

先从 [GitHub Releases](https://github.com/jiangtaoxu/dsh-plugin-codex-import/releases/latest) 下载 `dsh-plugin-codex-import-0.13.2.tgz`，也可[直接下载当前插件包](https://github.com/jiangtaoxu/dsh-plugin-codex-import/releases/download/v0.13.2/dsh-plugin-codex-import-0.13.2.tgz)。`Source code` 为源码归档，不是安装包；`SHA256SUMS` 用于完整性校验。

1. 打开左侧「插件」，点击「添加插件」旁的菜单，选择「安装第三方插件」。
2. 在安装来源中输入本插件安装包的绝对路径。使用 npm 文件 spec 可以保留路径中的空格，例如：

   ```text
   file:/absolute/path/dsh-plugin-codex-import/dsh-plugin-codex-import-0.13.2.tgz
   ```

3. 完成安装并启用插件。如果界面提示需要重启，重启 Harness。
4. 在任意会话的输入框执行以下命令。它们是本地指令，不会请求模型：

   ```text
   /codex-import preview
   ```

   ```text
   /codex-import run
   ```

无参数 `preview` 先打开上方来源选择向导；点击「开始预览」后，或使用 `preview {}` / `run`，会立即返回任务编号并打开进度窗口，后台读取并检查本地会话和附件。窗口显示已检查数量、百分比、当前会话、有正文/仅索引数量、可恢复附件和失败数量；此阶段不复制会话或附件。

预览完成后，窗口显示来源、目标目录和会话范围。点击 **「确认导入」** 才开始复制；点击「暂不导入」或关闭窗口不会开始导入。确认在完成预览后 15 分钟内有效，只能由发起预览的 Harness 会话使用一次；可用 `status` 重新打开。确认后读取本次成功检查的会话的最新内容，不加入预览后新增的会话；失败条目不进入确认范围。预览显示预计新增、源变化、源未变化数量；确认时读取最新正文和附件，实际更新结果可能因源内容或附件变化而不同。

**0.7.0 起 `run` 同样先预览并等待确认**，不会直接批量导入。已有 JSON 筛选选项仍有效。点击「后台运行」后任务继续，点击「取消预览」不复制内容；实际导入时点击「取消导入」停止后续处理，已完成副本保留。退出 Harness 后确认失效，需重新预览。

导入运行期间可随时执行以下指令：

```text
/codex-import status
```

重新打开当前/最近一次任务的进度窗口。任务状态保留在当前 Harness 进程中；退出应用会停止运行中的任务，重开后可再次 `run` 接续导入。

```text
/codex-import cancel
```

请求取消当前导入。进度推送使用 Harness 自带的后台任务与观察接口，不轮询执行指令，不启动模型，不把进度写入模型消息。

**0.9.0 起默认优先使用仍存在的原项目目录作为实际工作目录。** 例如原会话的 `cwd` 为 `/Users/you/repository/example` 且该目录仍存在，导入副本的 Harness 会话 `cwd` 和工作区都会指向此处，续聊时可在该项目目录工作。插件只关联目录，不复制或移动原项目文件；聊天日志仍写入 Harness 的会话存储。

原目录不存在、不是目录、无法访问，或未记录有效绝对路径的会话，回退到 `$DSH_HOME/imports/codex`（通常为 `~/.dsh/imports/codex`），工作区名称为「Codex 导入」。不会自动重建缺失的原项目目录，回退目录只在确认导入且有会话需要它时创建。回退副本用于历史查看，继续开发前需选择有效项目目录。

预览显示原项目会话数量、现有项目目录数量、回退数量与目标目录示例（前五个，按会话数量排序）。确认锁定本次每条会话的目录分配，原目录被移走、替换、符号链接目标改变或源会话更换目录时需重新预览；原本回退的目录后来恢复，也不会在确认时悄悄改变分配。

`groupByProject:false` 可保持原来的统一目录模式：

```text
/codex-import preview {"groupByProject":false}
```

若已有 profile 显式配置了 `groupByProject:false`，仍尊重该设置；使用 `preview {"groupByProject":true}` 可覆盖。以前导入的副本不原地迁移或改写，使用新的目录分配重新预览并确认后会创建独立快照，旧副本及 Harness 续聊继续保留。**不自动追踪导入后项目的改名或移动。**

桌面版也可以使用其自带 CLI 安装。**先完全退出 Harness 桌面应用**，再执行：

```sh
'/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh' \
  plugin --profile desktop add \
  'file:/absolute/path/dsh-plugin-codex-import/dsh-plugin-codex-import-0.13.2.tgz'
```

安装后重新打开应用。不要用 npm 安装的另一份 dsh 修改桌面版专用的 desktop profile。

## 统一侧栏目录与导入后刷新（0.10.0 起）

默认左侧工作区区域显示一个 **「Codex 导入目录」**，展开后按原 Codex 项目分组，项目下面直接列出导入对话名称。目录读取期间显示进度，读取失败显示原因和重试入口。支持折叠、搜索全部标题/项目/路径/ID、归档筛选与逐批展开，搜索先覆盖完整数据再分页。仅索引的记录有明确标识。

这里是界面收纳：原生工作区注册、每条会话的实际 `cwd`、原项目文件和聊天日志保持不变。普通工作区、手动聊天及混合工作区中的手动聊天继续单独展示。点击「原生侧栏」可恢复完整的 Harness 原生工作区管理界面；在顶部「Codex 导入目录」总面板点击「使用导入目录侧栏」可恢复收纳视图。插件卸载会自动恢复原生侧栏。

已修复直接持久化导入后会话列表未更新的问题：正式导入结束、失败或取消（可能已有部分写入）以及清理结束后自动刷新原生会话列表和收纳目录，避免只出现工作区文件夹、必须手动打开导入总面板才看到会话。此修复无需再次导入现有记录，也不改写旧副本或续聊。

## 按原项目浏览、搜索和折叠记录

点击左侧导航区的 **「Codex 导入目录」** 入口：

- 左侧按原项目名和原路径分组，同名但路径不同的项目保持独立；右侧列出项目中的会话。
- 可搜索全部已导入记录的标题、项目名称、原目录和 Codex 会话 ID。搜索在完整目录上进行，再分页展示，不会只检索当前显示的前 100 条。
- 支持全部、未归档和已归档筛选，点击标题打开已有的 Harness 副本，不产生新副本。
- 默认收纳侧栏将所有导入项目放在「Codex 导入目录」下；原生工作目录仍可指向有效的原项目，二者独立。

插件启动时会读取已有导入副本，并通过 Harness 的原生投影缓存补齐标题。因此未逐条点开的会话也能显示名称，并参与标题搜索；第一次整理会显示进度。新的导入会在写入时生成标题缓存。目录可通过「刷新目录」更新。此过程不启动 Agent、不调用模型、不改写对话正文。手动在 Harness 修改过的标题会保留。

导入记录中的终端输出、文件变更、MCP 和工具历史改为专用折叠卡片：默认只显示类型、命令摘要和行数；点击「展开记录」查看完整原文，长输出在固定高度区域内滚动，点击「收起记录」再次隐藏。图片查看和生成记录直接保留原生图片预览，长路径、完整生成提示词与来源说明默认收起，点击「展开详情」查看。普通用户消息和助手回复照常展示。**已有导入副本立即适用，不需要删除后重导**，折叠只影响界面，原文仍完整保留。卸载插件后这些内容依然能以原生文本查看。

## 结构化问答回复（0.6.0 起）

用户消息中的 `<send_user_message_question_reply>...</send_user_message_question_reply>` 会显示为「问题与回答」卡片，按原顺序逐项列出问题和回答，默认隐藏 `questionItemId` 和调用 ID。支持一次多题、多选数组、多行内容和空回答，点击「查看原始消息」可查看完整原文。

此功能使用 Harness 原生 UserText 片段扩展，只处理通过格式和字段校验的标签范围；消息前后的普通文字、原生附件、复制和消息身份继续保留。无效 JSON、缺失字段或不支持的结构回退为原文，Markdown 代码示例和行内代码保持原样。文本内容不会作为 HTML 或指令执行。

**已有导入副本无需再次导入即可生效**；存储的对话、Codex 原记录和模型历史内容不改写。图片显示优化也立即适用于旧版已导入的图片副本，缩略图与原图预览继续使用 Harness 的原生图片组件。

## 清理导入副本

在 **新建的 Harness 会话**中执行：

```text
/codex-import delete
```

此命令只扫描并打开删除确认窗口，**不会立即删除**。窗口显示插件导入副本总数、有 Harness 新增续聊的副本数，以及当前选择的删除数量：

- 默认保留有新增续聊的副本，只删除未续聊的导入副本。
- 勾选「同时删除包含 Harness 新增续聊的副本」后，一并删除这些副本及其 Harness 续聊。
- 根据当前选择输入「删除 N 条会话」，再点击「确认删除 Harness 副本」，才会开始实际清理。可以关闭窗口放弃操作。

清理覆盖本插件生成的所有导入快照及恢复副本，包括已归档记录。只删除 Harness 会话存储中的对应日志并解除侧栏关联；不删除 Codex 原位置的任何数据，不删除项目代码、外部附件、手动创建或手动分叉的会话，也不删除「Codex 导入」工作区目录。为空的会话目录和原生锁文件会保留，以遵循 Harness 的文件锁规则。

确认有效期为 10 分钟，只能使用一次，并绑定发起预览的会话。后端会重新校验来源、版本和路径；预览后有内容变化时需要重新预览。当前进程已激活的会话、被其他写入者占用的会话、目录中有额外文件或无法安全确认来源的记录会保留并报告；如需清理已激活记录，重启 Harness 后在新会话中重试。请勿从即将删除的导入会话发起清理。

删除过程显示进度，可停止后续清理；已完成的删除不会恢复。之后重新执行 `/codex-import run` 可从仍存在的 Codex 原记录重新导入，已删除的 Harness 续聊无法由 Codex 恢复。清理仅支持 macOS/Linux 的原生 JSONL 存储；自定义存储根目录需在插件配置设置 `harnessSessionRoot`（默认 `$DSH_HOME/sessions`）。

## 按项目或会话导入

命令后面可以附加 JSON 对象；路径中的空格无需另外转义：

```text
/codex-import preview {"cwd":"/Users/you/repository/example"}
/codex-import run {"cwd":"/Users/you/repository/example"}
/codex-import run {"threadIds":["原始 Codex 会话 ID"]}
/codex-import run {"codexHome":"/path/to/copied/.codex","includeArchived":false}
/codex-import run {"groupByProject":true}
/codex-import run {"workspaceTitle":"Codex 导入","importWorkspacePath":"/path/to/codex-archive"}
```

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| `codexHome` | `CODEX_HOME` 或 `~/.codex` | Codex 数据目录；支持从复制的目录导入 |
| `cwd` | 不限制 | 按原始项目目录精确筛选 |
| `threadIds` | 不限制 | 按原始 Codex 会话 ID 筛选 |
| `includeArchived` | `true` | 是否包含已归档会话 |
| `syncExisting` | `true` | 增量追加已有副本；`false` 使用独立快照模式 |
| `preserveArchive` | `true` | 是否在 Harness 中保留归档和置顶状态 |
| `groupByProject` | `true` | 优先复用现有原项目工作目录，失效时回退；`false` 始终使用统一目录 |
| `importWorkspacePath` | `$DSH_HOME/imports/codex` | 回退或统一导入目录；确认后有会话需要时才创建 |
| `workspaceTitle` | `Codex 导入` | 新建统一工作区的显示名称；已有工作区名称不会被覆盖 |
| `importAttachments` | `true` | 复制可恢复图片与明确附件 |
| `maxAttachmentBytes` | `104857600` | 单附件复制上限，字节；图片还受 Harness 自身限制 |

也可以在 profile 的 patch 中配置持久默认值。下列 patch **替换该插件整行配置**：

```yaml
- id: codex-import
  config:
    codexHome: /Users/you/.codex
    includeArchived: true
    syncExisting: true
    preserveArchive: true
    groupByProject: true
    workspaceTitle: Codex 导入
```

## 导入内容与保留方式

- 自动选择编号最高的 `state_*.sqlite` 和 `thread_history_*.sqlite`，通过只读连接访问 SQLite，兼容正在使用的 WAL 数据库。
- 读取会话索引、项目元数据、用户消息、助手回复、推理内容、终端记录、文件变更、MCP 调用和其他本地历史条目；读取实时条目和没有索引行的孤立历史。
- 扫描 `sessions/` 与 `archived_sessions/` 中的 JSONL。SQLite 正文存在时以它为聊天展示来源，JSONL 作为原始补充记录保存；SQLite 正文不存在时从 JSONL 还原消息，避免同一文件的 `event_msg` 与 `response_item` 重复展示。
- 用户和助手内容保存为 Harness 原生消息。工具操作以带说明的历史文本展示，**不会重新执行原来的命令或工具**。
- 原始条目保存在目标会话中的 `codex-import/raw` 事件，原始会话及项目元数据保存在 `codex-import/source`。这些事件标记为 `ignorable`，移除插件后仍可查看原生聊天内容。
- 原始标题和消息时间会保留。默认按现有原始 `cwd` 关联 Harness 工作区，失效目录回退到「Codex 导入」，不创建缺失的原项目文件夹；原始目录元数据仍保留。
- 子智能体原始身份和关联信息保存在来源元数据；不会把旧 Codex 子智能体注册为正在运行的 Harness 智能体。
- 只有索引、没有可恢复正文的会话也会导入，并显示「未找到消息正文」提示。这不代表已恢复不存在的内容。

导入器不会读 `auth.json`、不会读取凭据，不会修改 Codex 数据，不会调用模型或主动上传对话。你之后在 Harness 中续聊时，相关历史会随 Harness 的正常模型请求使用。

## 重复导入、中断和后续更新

**0.11.0 起默认增量同步**。在 Harness 新建或切换到一个普通会话后执行：

```text
/codex-import sync
```

`sync`、`preview` 和 `run` 都先只读预览，点击「确认导入」后才写入。目前为手动同步，不后台定时扫描。

- 新增的 Codex 对话创建一次副本；同一 Codex 数据目录、原会话 ID 和目标工作目录的已有对话复用原 Harness 会话 ID。完全未变化的会话直接跳过。
- Codex 新增消息按本次同步顺序追加。旧消息修订以新版本追加并显示「Codex 增量同步」说明；源端删除不会删除 Harness 已有历史。不会把新增消息插进原历史中重新排序。
- Harness 续聊的原生事件及已有导入事件保留原样，只在日志末尾追加。Harness 自定义标题保留；未自行改名时可跟随 Codex 标题更新。仅索引会话后来恢复正文时在同一副本补入。
- 若旧版已经有多个快照，优先选择有 Harness 续聊的副本；选定并完成首次同步后固定优先该副本。旧副本不自动合并或删除。更换目标工作目录仍是不同副本范围，不自动搬迁。
- 打开、运行或被其他写入者锁住的会话显示「待重试」，不会因此创建额外副本。切换到其他会话并关闭/释放该会话后再次同步；原生轮次未结束时先结束或恢复该轮次。
- 同步使用原生独占写锁和可恢复的追加事务。取消会先完成当前已开始的事务，再停止下一条会话；程序中断后再次同步可接续未完成事务，若有冲突则保留全部历史并报告失败。

预览锁定本次成功检查的 Codex ID、目标目录与已有副本 ID；确认时读取这些会话的最新内容，预览后新增的会话留待下次。可以按 `threadIds` 筛选同步。若希望继续旧的独立快照模式，显式传入 `{"syncExisting":false}`；来源或附件变化时生成新快照，相同快照跳过。

导入器只读 Codex。项目关联失败时已保存的正文仍保留，再次同步会重试关联；不会自动删除源端或 Harness 的历史。

## 长用户消息显示（0.11.0 起）

已发送的普通用户文本超过 1200 字符或 18 行时，默认最多展示前 900 字符、12 行；点击「展开全部」查看完整内容，再点「收起内容」恢复。展开后支持 A− / A＋ 调整 12–24px 字号，内容区域滚动，右下角可拖动调整高度。原消息未截断，原生复制、编辑、附件、引用与问答卡片保留；这是显示优化，也适用于之后在 Harness 发送的长文本。

## 图片和其他附件（0.5.0 起）

默认复制可恢复的附件到 **Harness 原生附件存储**，会话中的图片显示为缩略图，可点开查看；用户上传的普通文件显示为原生文件卡片。助手明确给出的本地文件下载链接也会复制，显示「打开附件」卡片。图片查看/生成条目中仍存在的本地图片会一同保留。所有原始条目仍保存不变。

支持的来源：

- Codex 消息中的 `localImage`、内嵌 `data:image/...;base64` 图片，以及显式本地文件附件。
- Codex 自动生成的「Files mentioned/pasted by the user」附件列表，只识别附件区内的明确路径，不把普通正文或终端日志中的代码路径批量复制。
- 优先从该对话的 JSONL 原始记录恢复当时内嵌的图片，避免临时路径过期、权限受限或原图已被修改；只关联用户文字完全一致且图片组唯一的记录，避免把其他问题的图片配错。
- 助手 Markdown 中明确的本地文件链接（代码块示例除外）；普通文件保留原始字节，图片经过 Harness 的原生格式验证与必要归一化。

原文件不存在且原始记录没有内嵌数据时，显示「附件未导入」及具体原因；远程 URL 不自动下载。PNG/JPEG/WebP/GIF 可作图片展示；SVG 等其他格式按普通文件保存。单附件默认上限 100 MiB，图片另遵循 Harness 自身的字节、像素和格式限制。外部路径文件按当前本机版本复制，无法证明已经修改过的文件仍与历史时刻完全一致。

```text
/codex-import preview
/codex-import run
/codex-import run {"threadIds":["原始 Codex 会话 ID"]}
/codex-import run {"importAttachments":false}
/codex-import run {"maxAttachmentBytes":209715200}
```

`preview` 检查可恢复数量和缺失原因，不复制附件。0.11.0 起确认后在原副本中追加需要补入的附件消息，原有消息及 Harness 续聊保留；相同来源和附件重复同步会跳过。原路径后来失效也不会移除已导入的附件。只有显式关闭 `syncExisting` 时，附件变化才沿用旧版独立快照模式。

附件由 Harness 的内容寻址存储去重，保存后不依赖原路径，重启或源文件消失后仍可读取。清理指令删除对应会话记录和引用；Harness 的全局共享附件库遵循原生保留规则，不自动物理清扫，以免影响其他会话使用的同一附件。

Codex 的 `history.jsonl` 提示词列表不能替代完整会话正文。本地未保存的正文、图片或文件无法恢复；插件不会恢复原模型内部状态或原来的自动化任务。

## 附件分类统计与明细（0.8.0 起）

预览和导入窗口分别显示可恢复/不可导入的图片、文件，均采用「去重项数 / 引用次数」。点击 **「查看附件统计与明细」** 查看分类汇总，展开「按缺失原因查看统计」可查看原因与两类附件的数量；下方支持类型、状态、原因筛选及文件名、路径、对话标题、Codex ID 搜索。搜索覆盖完整报告，然后每页展示 30 项。展开一项可查看完整来源、详细失败原因、关联对话和消息标识。

缺失原因包括原文件不存在、无读取权限、大小或像素超限、图片格式/数据异常、远程附件未下载、路径异常、复制期间发生变化、服务不可用及其他错误。

去重规则：本地附件按规范化的绝对来源路径，内嵌图片按字节内容摘要；跨消息和跨对话合并，同名不同目录保留为不同项。不按内容合并不同路径，不解析符号链接为同一物理文件。图片根据消息类型、成功识别结果或支持的图片扩展名判断，其他附件归文件。带 `#L123`、`:123` 等行号的代码位置跳转链接单独统计，可在状态筛选中查看，不计入可恢复或不可导入的附件；无法确定来源的引用独立计数。各类型、恢复状态、原因分组分别去重，同一来源在不同历史记录中可能恢复结果不同，原因分组的去重数不能直接相加作为总数。

明细只保存在当前 Harness 进程内，保留最近三次任务；重启或被后续任务替换后需重新预览。后台任务仅传递汇总数据，完整明细通过 Harness 原生认证接口按需分页读取，不写入对话内容、不上传外部服务。

## 旧版续聊记录的兼容性恢复

新版新建的会话包含空的系统消息头，保证后续续聊与冷重开使用 Harness 要求的消息结构。对于旧版导入后已经续聊、且明确报出 `system/message requires a protected first surface head` 的会话，重新导入对应源会话时会校验并创建独立恢复副本，保留新增的续聊消息；恢复副本标题带「已恢复」，原始记录保持字节不变并归档。只自动处理已验证的这一类错误；其他损坏、压缩或图片卸载后的复杂记录会明确报告失败，不覆盖源文件。
